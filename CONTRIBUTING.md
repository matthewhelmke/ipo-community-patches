# Contributing

Thanks for considering a contribution! This file covers the practical
details: what we accept, how patches are validated, the PR checklist.

The high-level "what / why" lives in the [README](./README.md). Read
that first if you haven't.

## What we accept

| Kind | Accepted | Notes |
|---|---|---|
| Translations (cp1252 languages) | ✅ | The common case |
| Translations (non-cp1252) | ✅ with caveat | Inpax-runtime only; not compatible with stock INPA — flag in PR |
| Label cleanups (typos, abbreviations) | ✅ | |
| Numeric overrides (default thresholds, etc.) | ✅ | Explain *why* in the patch's `description` |
| New `.IPO` scripts | ❌ | Submit to [inpax](https://github.com/emdzej/inpax) — this repo is patch-only |
| Modified IPO binaries | ❌ | The point of this repo is reviewable patches, not opaque binaries |
| Reverse-engineered IPS sources | ❌ | Different repo, different licence concerns |

## File naming

```
<IPO-basename>.<purpose>.<author-tag>.patch.yaml
```

- `IPO-basename` — the source IPO with its extension dropped (e.g.
  `RADIO`, `MS43`, `LCM_E46`). Case-insensitive; use whatever case
  matches what's in the BMW install you're patching.
- `purpose` — short tag describing the patch's intent. Languages use
  ISO 639-1 codes (`en`, `de`, `pl`, `cs`, …). Non-translation
  patches use a descriptive slug (`fix-typo`, `cleaner-labels`,
  `low-temp-threshold`).
- `author-tag` — your GitHub handle, or another stable identifier
  multiple of your patches can share.

Examples that look right:

```
patches/inpa/sgdat/RADIO.en.emdzej.patch.yaml
patches/inpa/sgdat/MS43.pl.someone.patch.yaml
patches/ncsexpert/cfgdat/E46.fix-typo.contributor.patch.yaml
```

## Patch file requirements

Generated by `inpax-ipo-editor patch init`, but if you're hand-rolling
one, here's the schema:

```yaml
inpax_patch_version: 1
original:
  name: <IPO-basename-with-extension>      # e.g. RADIO.IPO
  location: <inpa | nfs | ncsexpert>
  checksum:
    algorithm: sha256
    value: <64-char-lowercase-hex>
target_encoding: cp1252                    # see README "Encoding caveat"
description: |
  Short paragraph: what this patch does, what language / purpose.
patches:
  - index: <integer>
    type: <string | int | long | byte | real | bool>
    value: <new value>
    notes: |
      Optional. Where this constant is used in the IPO.
```

Required fields: `inpax_patch_version`, `original` (with all three
sub-fields), `patches`. Everything else is recommended but optional.

## Pre-submission checklist

Before opening the PR, verify locally:

```bash
# 1. The patch applies cleanly to a real IPO.
pnpm exec ipo-editor patch apply \
  /path/to/source.ipo your-patch.yaml --dry-run

# 2. The result is byte-valid (apply + re-read).
pnpm exec ipo-editor patch apply \
  /path/to/source.ipo your-patch.yaml -o /tmp/result.ipo
pnpm exec ipo-editor /tmp/result.ipo --readonly
# Browse through, confirm your strings appear correctly.

# 3. If your patch is non-cp1252, test the encoding round-trip in
#    inpax — load /tmp/result.ipo with --input-encoding cp1250
#    (or whatever you targeted) and verify the strings render.
```

If any of those fails, fix and re-test before submitting.

## PR template (copy-paste into your PR body)

```markdown
## Target

- IPO: `RADIO.IPO`
- Install path: `EC-APPS/INPA/SGDAT/`
- BMW product: INPA (works identically in NFS / NCS Expert if the
  same IPO ships there)

## What this patch does

<2-3 sentences>

## Encoding

- target_encoding: cp1252
- Compatible with stock INPA: yes / no

## Testing

- [ ] Applied via `ipo-editor patch apply` against my own IPO
- [ ] Verified the result reads back correctly in `ipo-editor --readonly`
- [ ] (Optional) Loaded the patched IPO in inpax / real INPA and
      visually confirmed the new labels

## Source

<If derivative: link to the original translation / glossary you're
adapting. Otherwise: "Original translation.">
```

## What happens after you open a PR

A maintainer (currently a small handful of people) will:

1. **Schema-validate** by running `ipo-editor patch apply --dry-run`.
2. **Spot-check** the YAML for naming convention compliance.
3. **Comment if anything needs adjustment.** Schema fixes are tiny;
   we'd rather iterate with you than reject.
4. **Merge** once the PR passes checks.

There's no contributor licence agreement and no extra paperwork. By
opening a PR you agree to release the patch contents under CC0 (see
README).

## Style notes for translations

- **Keep label length** roughly comparable to the original — INPA
  paints into a fixed 80-column grid, and a label that grows from 8
  to 30 characters may clip in the UI.
- **Preserve technical terms** when the original deliberately uses
  English (lambda, EWS, DME, etc.) — those map to physical components
  and shouldn't be localised.
- **Match the register** of the original — INPA's German is terse,
  technical, sometimes brusque. A translation that becomes
  conversational reads oddly next to neighbouring labels.
